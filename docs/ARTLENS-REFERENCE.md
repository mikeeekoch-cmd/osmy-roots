# ArtLens reference: what carries over

Reviewed September 10, 2026. Public reference: [djvaroli/artlens-ai](https://github.com/djvaroli/artlens-ai), latest inspected commit `4d5c588122de` (March 5). Its March history added a demo, documented third place, fixed the logo and refined the README. The supplied local copy's 16 authored text/configuration files match the earlier complete read; its README differs from the current public README.

The public presentation includes a mark, direct product promise, demo video, numbered pipeline, feature modes, stack, prerequisites, run commands, structure and MIT license. Roots now follows that useful documentation structure, with a new original SVG mark and an explicit preparation status. App/demo links will be added only after they exist. No ArtLens code, prompts, branding assets or video are copied.

| ArtLens pattern | Roots plan |
| --- | --- |
| One artwork becomes an emotional documentary | Scattered family material becomes a map and a readable chapter |
| Automatic interpretation after upload | Mixed intake with editable people and story proposals |
| Intermediate research dossier | Sources, claims, stories and reviewed relationships with exact references |
| Staged work and cached partial results | Persist completed items, show real progress and resume |
| Accessible research links | Click a relationship or sentence to its evidence |

The local ArtLens source includes client-side API-key injection, loosely checked model JSON and simulated live progress for cached output. Roots should instead make model calls server-side, validate shared schemas and label saved results. Exact claim citations, user/project isolation and correction dependencies are central to Roots, not cosmetic additions.

ArtLens source and assets remain prior work even where MIT permits reuse. Hackathon implementation must be original event work and documented in BUILD-LOG.md.
