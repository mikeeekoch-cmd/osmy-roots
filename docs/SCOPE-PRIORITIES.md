## Search and crawling, exact placement

File bytes → Claude's parser → normalized sources → Claude's local index / bounded public fetch → Mike's Astra analysis → pending proposal → Natalia's Q&A → Mike's saved decision → Natalia's updated canvas → Mike's cited passage → Claude's PDF/ZIP.

Public retrieval is a separate backend operation, not a UI animation and not an assumed capability of an ordinary model text response. P0 has two explicit retrieval functions: searchLocalSources and fetchPublicRecord. Use a concrete permitted public URL selected from the private source playbook or supplied by Mike. If unavailable, ask Mike for the source and continue local search. Do not fabricate a found archive record.

A P0 source fetch retrieves one page with a bounded response size and short timeout. Validate destination/redirects, block private/local network destinations, retain URL/retrieval time/quote and return a visible failure for login, CAPTCHA or blocked access. No login bypass or broad recursive crawl. A successful unrelated page does not establish an ancestor match.

P1 searchWeb uses an already configured provider and returns URLs/snippets; fetch candidate pages before treating snippets as evidence. P1 crawlSource follows a maximum of three allowed same-site links and deduplicates visited URLs. Keep each hit separate until review supports identity. Do not spend the remaining sprint configuring many providers or social-account access.
