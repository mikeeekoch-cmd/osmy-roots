# Local demonstration

## Round 2 ordinary-document route

The current engineering demo runs locally on port 3200. Configure `ROOTS_DEMO_MANIFEST` to the frozen private manifest and upload only its `01-upload` selection. The final packet has 20 files: a personal PDF, natural family notes, photo notes, three reconstructed English chat ZIPs and 14 unchanged original photographs. Presenter cues and the manifest stay outside the upload selection. Earlier register and photo-pair packets remain supported.

1. Enter the starting person and family geography, or choose geography unknown. Select all 20 frozen files and click Start the search. No project or model work starts before this click.
2. Review seven short sourced checks. Confirm, correct or choose I don't know explicitly. The recollection check comes from a live Astra interpretation. Its original quote and uncertainty remain inspectable. The final conflict stays unresolved when the presenter chooses I don't know.
3. After all seven answers, inspect the first five-person branch. Six saved arrivals extend the family to 35 people and 56 supplied relationships. Open a person card and an original photograph while work continues. Refresh resumes the saved run. Activity labels distinguish prepared family records from live model work; live websites remain zero for this packet.
4. Preview the current illustrated PDF in the workspace, then click Download family book. The server seals the matching reviewed state and serves the actual PDF, HTML, portable project JSON and unchanged originals in one ZIP.
5. Extract the ZIP to reopen elsewhere. Select project.json plus all files from photos/ and uploads/. Reopening restores source evidence, review history and original bytes without another model call. The reopened project is editable; a correction makes its previous book stale.

The Submit-to-Download budget is measured internally. No timer appears in the product. Opening narration comes before Submit and the dedication can follow Download. Use the separate private revised English cue script and seven-answer sheet. See READINESS.md for the two final measured browser runs and the exact tested code revision.

Supplied records, reconstructed dialogue, English source derivatives, captions and release schedules are prepared. Astra interpretation and current passage generation run live, with explicit human review between them. The demo demonstrates assembling a supplied family; it does not establish new external archive discoveries. Original/Enhanced comparison is available for older projects with supported pairs, but the final packet uses originals only.

## Earlier public-safe example

Start with pnpm dev and open http://127.0.0.1:3000. The server needs a funded OPENAI_API_KEY and OPENAI_MODEL=gpt-6-astra. Use New project to return to input without deleting a saved project.

## 2-3 minute public-safe route

1. Enter Alex Morgan, select geography unknown and the prepared synthetic example. Click Start the search. Explain that the five people, portrait and date discrepancy are fictional prepared inputs.
2. Paste: "I remember my grandfather Alex Morgan repairing watches in his workshop." Click Add to the investigation. The actual local search and Astra analysis appear in the activity panel. Websites should remain zero.
3. Read the live question and exact original quotation. Wording varies by model response; the question should ask whether the interpretation or intended Alex is correct. Click Accept. Open Alex's card to show the attributed memory, source locator and saved history. The conflicting birth years remain disputed.
4. Click Download family book. Astra writes a short current passage, and the app downloads a ZIP. Open book.pdf to show the portrait, five-generation branch, cited memory and unresolved dates. book.html is a readable alternative.
5. Extract the ZIP. Click New project and choose project.json plus the files inside photos/ and uploads/. Start the search, then inspect the retained story, evidence and history. Matching originals are recovered by hash; the same machine can also reuse its saved originals.

The direct live acceptance runs took 9.3 and 7.4 seconds for analysis, generation, ZIP creation and JSON reopen. Network/model latency can vary. They are measured checks, not a latency guarantee.

## Review and failure checks

For an unknown example, add "I remember Alex Morgan keeping a notebook beside the watch-repair bench." Choose I do not know, refresh and show that no story was accepted and the book remains current. Open the unanswered question and revisit it to accept or correct it. An accepted change marks the previous passage stale; Download regenerates it.

Repeating a source or review must not duplicate a story or inflate counters. Correct interpretation preserves the original quote. Person/relationship editors record human changes and offer one-level undo. Failed requests retain the original source and show an error; fix access and retry the same clue.

## What to say accurately

The application runs real Astra interpretation and current prose generation. It validates cited quotes and preserves human decisions. The layout, example family and placeholder portrait are prepared. Local evidence search and bounded public retrieval are distinct operations. The Library of Congress adapter check retrieved a public page; it established no family match.

The private example enriches provenance for a memory already present in prior family material. Importing supplied people is not model discovery. The tested English reconstructed chat ZIP format and bounded PDF extraction are supported. Arbitrary chat exports, OCR, restoration, broad archive search, cloud deployment and an independently editable HTML map are deferred. Extract a complete project ZIP before selecting its JSON and originals for reopen.

No recording, public deployment, competition submission or private-family publication has been performed by the coding checks. Review any public demo material before sharing it.
